Model Context Protocol (MCP)

Purpose Let UDAW's AI assistant use tools from external MCP servers (a sample librarian, a documentation server, a project-management server, ...) in the same conversation as the built-in DAW tools - and, in the other direction, let an external MCP-aware client drive UDAW itself through its own safe command API.

Why MCP (Model Context Protocol) is the emerging standard for connecting an AI assistant to external tools without hand-writing a new integration for each one. UDAW treats every MCP tool call as informational context for the model rather than a direct DAW mutation, so connecting an unfamiliar third-party MCP server can never bypass UDAW's own edit-validation and confirmation rules.

Consuming external MCP servers (the common case)

  1. On the AI tab, fill in MCP name (a short label you choose) and MCP command line. UDAW picks the transport from what you type: anything starting with http:// or https:// is treated as an MCP-over-HTTP server (a plain JSON-RPC request/response POST to that URL - there is no streaming/SSE support yet, so a server that only pushes notifications over SSE will not work); anything else is launched as a local child process that speaks MCP over stdio, newline-delimited JSON-RPC on its stdin/stdout (e.g. mcp-fs-server --root C:\Samples).
  2. Press Test. UDAW starts the transport, performs the MCP initialize handshake (protocol version 2024-11-05, identifying itself as client "UDAW"), then calls tools/list and logs the server's name/version and every tool's name and description to the AI log. This is a one-shot connect-list-disconnect check, not a live connection - use it to confirm a server is reachable and see what it offers before relying on it in a real conversation. A server that never answers within its timeout (10 seconds by default) fails the test rather than hanging the UI.
  3. Press Add to save it to your configured server list, written to a UDAW-wide config file (mcp_servers.cfg in your UDAW config directory, independent of any open project) so it persists across restarts and across every project you open. Remove it the same way when you no longer need it.
  4. Once added, every chat conversation automatically connects to every configured server and tells the assistant what tools each one offers - the assistant can then call one of those tools mid-conversation (e.g. "search the sample library for a snare") and the result is fed back as context. MCP tool results never directly change your project - if you want the AI to act on what it found, ask it to do so via an ordinary DAW tool command (see Chat & Tool Commands), which still goes through the normal validated, undo-safe path.
A misbehaving or unreachable MCP server never blocks the DAW or the UI - it just contributes no tools for that conversation ("that tool is unavailable"), exactly like a built-in AI provider with no key configured.

Authentication and environment: the HTTP transport sends plain JSON-RPC with no built-in header/token field, so an HTTP MCP server that needs authentication must accept its credential embedded in the URL itself (e.g. a token query parameter) unless you are willing to hand-edit mcp_servers.cfg. A stdio server, by contrast, can be given extra environment variables (an env=NAME1=VAL1;NAME2=VAL2 line in that same config file, layered on top of UDAW's own process environment) - useful for passing a credential to a local MCP server without putting it on the command line where it would show up in a process list. There is no in-UI editor for these yet; set them by editing the config file with UDAW closed.

Resources and prompts: UDAW's MCP client can already fetch a server's resources/list/resources/read and prompts/list/prompts/get at the protocol level, but the AI chat only surfaces a connected server's tools today - resources and prompts are not yet pulled into the conversation automatically.

Exposing UDAW as an MCP server (advanced)

UDAW can optionally expose its own safe DAW command API (the same tool table listed in Chat & Tool Commands) as an MCP server of its own, so an external MCP-aware client - Claude Desktop, a local model, another application - can drive UDAW directly over plain HTTP/JSON-RPC (one request per connection; no SSE/streaming, no TLS - treat it as a trusted-local-network tool, not something to expose past your own machine). This is off by default and binds to 127.0.0.1 (loopback only, not reachable from the network) unless you change the bind address yourself.

  1. On the AI tab, check Expose UDAW as an MCP server and set the port (default 8765) and bind address (default 127.0.0.1; leave it unless you specifically understand the exposure you're creating by changing it).
  2. Leave Allow destructive tools unchecked to only permit the read-only tools from the table below from external clients - a safe default for letting something look at your project without being able to change it.
  3. Check it if you want an external client to also be able to run structural/destructive tools; even then, each destructive call additionally requires the external client to pass an explicit confirm: true argument, so a client can't destructively mutate the project through one blind call.
  4. Every call an external client makes - destructive or not - runs through the exact same dispatch/undo-stack path as a chat-driven or mouse-driven edit, so it always lands on the undo stack and is subject to the same validation.

The full set of DAW tools UDAW exposes, whether called by its own chat assistant or by an external MCP client connected to Expose UDAW as an MCP server:

Read-onlyReversible editDestructive (requires confirm: true from external MCP clients)
GetProjectInfo, GetTracks, GetTrackInfo, GetMixerState, GetSelection, AnalyzeAudio, SuggestMix, FindSample SetGain, SetPan, SetMute, SetSolo, AddMarker, CreateAutomation AddTrack, MoveClip, SetTempo, ExportProject, GenerateMusic, AddSampleToTimeline
Only enable exposure with a bind address you understand, and only leave "Allow destructive tools" on while you trust whatever client will be connecting - it can mutate the open project (add tracks, change tempo, export, trigger a paid Suno generation) subject only to the confirm-flag requirement described above.
